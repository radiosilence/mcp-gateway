- **Everyone signs in to the dashboard again once, and stored secrets are bound to their rows.** Session ids are now stored as their SHA-256, so read access to the database no longer yields live sessions; existing sessions are dropped by migration. The cookies move to `__Host-session` and `__Host-oauth`, which a sibling subdomain cannot set or shadow, and the old names are cleared. Each sealed credential is now bound to its user and MCP, so one copied into another user's row no longer opens; credentials stored before this are resealed at startup. Rolling back to an earlier version after this one has started leaves stored credentials unreadable, so roll forward instead.
